# Coverage matrix — trade, inventory, accounts

**Purpose:** make "fully covered" a *verifiable* claim rather than an assertion.

The honest test of "did we investigate this DocType" is not whether its name is mentioned —
names like `Account`, `Item` and `Budget` appear on nearly every page — but whether its
**controller file is cited with a line number**, which only happens if someone read the code.

Reproduce with:

```bash
python3 tools/coverage_audit.py              # summary + gap list
python3 tools/coverage_audit.py --markdown   # the table below
python3 tools/coverage_audit.py --json       # machine readable
```

## How to read the columns

| Column | Meaning |
|---|---|
| **Controller cited** | its `.py` controller is cited at a line number in `docs/` — genuinely read |
| **Uncited (submittable)** | a **posting document** whose controller has not been read — a real gap, because submittable means it writes ledgers |
| **Uncited (config)** | a master or configuration table not yet read — matters where it *determines* posting behaviour (tax rules, pricing rules, payment terms) and matters much less where it is a lookup |
| **Excluded** | a deliberate decision, with a reason, recorded in `EXCLUDED` in `tools/coverage_audit.py` |

## Deliberate exclusions

Recorded in code so that an uncovered DocType is either a tracked gap or a decision, never an
oversight:

| Group | DocTypes | Reason |
|---|---|---|
| Equity / cap table | `Share Transfer`, `Share Type`, `Shareholder`, `Share Balance` | not ERP core |
| Vendor rating | `Supplier Scorecard` + 4 related | no ledger impact |
| Quality | `Quality Inspection` + 3 related | deferred to **Tranche B (quality)** by decision |
| Debug / maintenance | `Bisect Accounting Statements`, `Bisect Nodes`, `Ledger Health`, `Ledger Health Monitor` | diagnostic tooling; the *reason they exist* is covered in doc 22 §2.3 |
| Import tools | `Chart of Accounts Importer`, `Bank Statement Import` (+log) | one-time import paths |
| Trivial lookups | `Industry Type`, `Sales Partner Type`, `UOM Category`, `Warehouse Type`, `Bank Account Type/Subtype`, `Account Category`, `Dunning Type`, `SMS Center`, `Quick Stock Balance` | single-column lookups with no behaviour |
